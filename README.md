# 仓库周期分析原型

面向仓库管理员的网页：导入现有Excel，查看长期倾角变化、多点共同变化、疑似沉降区域线索，生成可追溯的周/月报告与完整PDF。

## 启动

使用Python 3.11或更新版本创建环境并安装依赖：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn vault.app:app --host 127.0.0.1 --port 8765
```

Windows PDF默认嵌入系统的微软雅黑字体。其他系统通过 `VAULT_REPORT_FONT` 指定中文TrueType字体路径。此原型绑定本机地址，未配置账号或公开部署。

安装完成后，Windows可双击 `start.cmd` 启动。

## 管理员流程

1. 使用“载入演示仓库”，或创建仓库后导入自己的Excel。
2. 在“仓库配置”上传俯视布局图，选择设备并点击位置，填写点组，然后保存。
3. 选择周评估（最近7天）或月评估（最近30天），截止日期默认最新数据日期。
4. 查看长期参考偏移、近期持续变化和区域线索。点击设备看完整历史，或在时间矩阵里切换每日/月度视图。
5. 在“资料档案”补充资料来源、安装信息，以及载荷、安装、校准等现场变更；允许资料未知。
6. 在“异常追踪”查看跨周期事项，记录处理状态及现场检查。也可在点位详情中开始人工追踪。
7. 补充检查后生成新评估，将当时的资料、处理和检查快照纳入网页报告与PDF；在“报告记录”回看旧报告。

公开版本的演示仓库、设备编号、读数和布局均由程序合成，与真实仓库无关。模拟结果用于体验流程，不作为现场验证证据。私有数据仅由使用者在本机导入。

## 数据与数学定义

- 读取原Excel的 `Result` 明细，不使用透视表或IT的 `flag` 作为真值；不要求修改Excel格式。
- 必须有 `name`、`message_type`、`angle_x`、`angle_y`、`event_time`。可选数值字段包括温度、供电、信号、双轴位移、初始偏移及原表合成值。
- 角度单位为度，位移单位为mm。保留原始位移；新增二维距离 `hypot(x_displacement, y_displacement)`。
- 原表 `x_y_displacement` 原样保留；来源系统可能采用绝对值之和，不等同于二维距离。原系统门槛不自动移用到新指标。
- 双轴角度变化幅值为参考时期与当前周期双轴中位数之差的欧式范数，作为变化特征，不称作独立的绝对倾斜角。
- 水平位置变化距离为双轴位移相对参考时期的向量变化；不等于“当前二维距离减参考二维距离”。
- 缺失值不是零。缺位移时可以继续做角度分析，不能填出不存在的位移。
- 同一仓库按设备、事件时间、消息类型去重；同一身份但内容不同则拒绝整次导入，保留原记录。记录保留完整原始列和源导入身份，原Excel按SHA-256留存。
- 原文件按导出本地时间分日。`source_timezone`记录口径，当前不会自动改写或转换历史时间。带时区的导出需要先明确统一口径。

## 分析方法与可调项

心跳先按日取中位数；每一天的统计权重相同。报警帧独立计数，不把持续超限的重复上报混进趋势。

默认参考时期为各设备最早数据覆盖充分的7个日历日：角度达到最低可用天数条件；如果存在位移数据，双轴位移也需要达到同一覆盖条件。这避免让缺少位移的最初记录成为永久空缺基线。未找到合适时期时保留最初时期并显示不足。也可指定共同参考日期，指定后不自动替换。

参考时期只是比较起点，并未认证为正常/安全。自动选择基于当时已导入、且在截止日期内的数据；补录更早历史可能改变新报告的自动参考期，因此长期正式使用建议明确指定参考日期。旧报告始终保留当时的实际参考日期和统计值。

近期趋势采用当前周期有效日统计值与实际日期的线性斜率，单位度/周。持续性检查相邻有效日的变化是否多数沿着总体趋势方向。满足参考变化、趋势强度、方向一致率和最低可用天数条件，才标为“近期持续变化”。长期参考差异另行显示，不能因为近期平缓就隐藏。

空间线索需要同一配置点组至少两个已定位点持续变化，并且共同日期的变化幅值具有足够相关性。先形成“区域调查线索”；只有轴向全部确认后才额外比较是否朝点组内部变化。布局方向采用图像宽高比和配置的符号/旋转；这仍是示意，不能确定实际沉降中心。

网页可配置：

- 评估周期、截止日期、参考日期和参考天数。
- 参考变化条件、近期趋势强度、方向一致率、最低可用天数、共同变化相关性。
- 每个点的位置、分组、显示名、货架高度、预期心跳周期、轴向核对和旋转/符号。
- 独立的最大轴角度及二维距离业务关注门槛；填写门槛必须填写依据和适用条件。

演示分析条件可调，不是工程安全阈值。高度只记录现场资料，不会重算已导入的位移；预期心跳周期用于检查超过1.5倍周期的内部长间隔。温度仅展示/计算关联，不自动补偿。

位移字段可能来自倾角换算，其来源与初始偏移含义需向使用者或厂家确认。系统不把换算位移当成独立沉降证据，也不反算地面沉降深度、判断事故概率或给出货物掉落结论。

## 自动报告与后续接入

### 资料与检查闭环

- 设备资料分别记录点位、轴向、高度、点组、安装日期、连接关系及预期上报周期的状态：待确认、推测、已确认。确认需要来源、日期和确认人。
- 仓库保存地面高程基准、整体连接关系、备注，以及布局、固定参考时期、业务门槛和时间口径的资料状态。没有固定参考日期时不能确认固定参考时期。
- 原有数据和点位继续读取，不自动认定已有现场依据。旧的轴向布尔值不再替代有依据的确认；方向示意由轴向资料的确认状态控制。
- 对应数值变化后，未经更新的原推测或确认依据重置为待确认。例如旋转角改变后，需要重新确认轴向。清除点位也会重置旧定位依据。
- 每次资料、点位、布局或参数修改保存前后值；现场变更另存实际发生日期、类型、位置、关联设备、记录人、可信程度及来源。不自动将变更认定为倾斜原因。
- 资料档案可以下载首次现场验证模板：`web/field-checklist.md`。优先收集安装方向、结构连接、稳定基准下重复的地面高程，以及载荷 / 安装 / 校准调整记录。

### 跨周期异常档案

- 新评估为持续倾斜、长期参考差异、已配置业务关注门槛及区域共同变化建立独立事项；原有报告不回填事项。
- 同一设备同一类发现延续同一档案，重复评估只追加周期记录。区域按点组名称与完整设备范围识别，范围变化后另建事项，旧范围显示无法继续比较。
- 每期区分“触发”“未再次触发”“无法评估”和“人工点已复看”。缺数据不等于恢复；处理状态由管理员控制，不自动关闭。
- 状态包括待查看、待检查、观察中、已处理。每次处理保存记录人及说明，旧记录不覆盖。已处理后再次触发显示待复核，并进入待处理范围，原状态保留。多个页面同时修改状态时，过期版本被拒绝，避免覆盖他人处理。
- 检查记录保存检查日期、人、位置、观察、措施、原因程度、依据及后续安排。原因允许未知，确认原因必须填写依据。检查记录不会自动改变分析规则或处理状态。
- 一条检查可附PNG/JPEG照片、PDF、UTF-8 CSV/TXT，单个10MB。附件按校验值留存，下载路径检查仓库和档案归属。PDF包含附件目录及SHA-256，原附件从对应检查记录下载。
- “载入模拟流程案例”单独保存明确标注的模拟处理与检查，默认不显示；模拟事项不参与真实计数、传感器分析或评估PDF，也不能变成真实事项。
- 报告保存生成时的追踪、资料与修改历史。评估截止日期是传感器数据截止；检查可能晚于该日期，PDF明确给出生成时间与各检查日期。后来补充的处理、检查和附件不修改旧报告，需要生成新评估。

### 实现边界

当前是单机、无账号的原型；记录人由用户填写。检查历史为追加记录，错误可追加说明；尚未设计客户的角色权限、正式复核流程或电子签名。沉降量反推、工程危险门槛、温度补偿与误报 / 漏报校准留待客户现场测量后实现。网页和批处理共用报告服务，数据、资料、追踪更新及报告快照在一次数据库事务中保存。

网页导入/评估接口可供现有系统调用，接口说明在 <http://127.0.0.1:8765/docs>。分析和保存逻辑集中在 `vault/service.py`，网页和批处理共同调用。

IT也可以定期导出原格式Excel后运行：

```powershell
.venv\Scripts\python.exe -m vault.batch --warehouse WAREHOUSE_ID --excel "export.xlsx" --cycle month --output "output\pdf\report.pdf"
```

`WAREHOUSE_ID`可从 `/api/warehouses` 查询。批处理会去重导入、保存报告、生成PDF；退出码非零时需要核查错误。本项目未创建任何实际定时任务。

每份报告保存：截止日期、周期、参考数据、参数、设备配置、不可变布局文件、全部日统计值、完整历史月度矩阵、来源校验值及算法版本。PDF使用这一结果，配置变更不会改变旧报告。

## 文件结构

`vault/importer.py`负责Excel适配与重复/冲突检查；`vault/analysis.py`负责统计和区域证据；`vault/storage.py`负责SQLite；`vault/service.py`负责生成/保存报告；`vault/report.py`负责PDF；`vault/app.py`提供接口；`web/`为无需构建的网页。

运行数据在 `data/`，PDF在 `output/pdf/`，不会覆盖使用者上传的原始文件。备份时保存整个 `data/` 目录及配置；源文件和布局需要与数据库一起保留。

## 针对性检查

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试覆盖欧式距离与缺失值、报警帧权重、固定参考与持续趋势、稀疏数据、区域方向资料门控、缺失月份、截止日期隔离、重复/冲突回滚、多仓库隔离、保存结果不受参数与点位修改影响，以及PDF导出。

浏览器检查只使用程序生成的模拟数据。需要Node.js、Playwright和本机Chrome：先运行 `.venv\Scripts\python.exe scripts/make_demo_excel.py`，设置 `VAULT_NODE_MODULES`（安装Playwright的node_modules目录）、`VAULT_BROWSER`（Chrome路径）及 `VAULT_QA_URL`（默认http://127.0.0.1:8766），在独立测试数据目录启动服务后运行 `node scripts/check_browser.cjs` 或 `node scripts/check_workflow_browser.cjs`。前者检查导入、曲线、矩阵、重复导入、PDF和窄屏；后者检查资料、处理、检查附件及报告快照。不要将浏览器流程检查连接正式使用的数据目录。浏览器和统计验证不等于现场沉降模型已经得到验证。

后续现场最重要的补充：位移字段定义、设备校准和安装轴向、货架连接关系、载荷/维护事件，以及稳定基准下的地面高程复测。

## 公开仓库与本地隐私

仓库仅包含代码、依赖、文档和合成测试。`.gitignore` 排除运行数据、数据库、导出物、原始Excel、图片、产品资料、环境文件和密钥；提交时还应核对实际文件清单，不能只依赖忽略规则。

可选的 `data/private-demo.json` 用于本机私有演示，包含 `name`、`excel`、`layout` 和 `devices` 配置。这份文件及其引用文件不能提交或分享；公开版本不内置任何真实点位、布局或源文件名。没有私有配置时，演示入口自动使用合成数据；`POST /api/demo?synthetic=true` 始终选择合成演示，适用于隔离的浏览器检查。
